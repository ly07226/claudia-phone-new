# 后台 AI 执行器：上线前安全契约

## 当前真实边界
- 已有队列登记、只读任务/回复查询、前台恢复时的本地同步与 Web Push 发送器代码。
- **尚无能够独立调用 AI 的 worker**。现有入队接口只保存会话 ID、消息 ID、时间线和幂等键；云端并不知道完整提示词、角色设定、历史或服务商凭据。
- 绝不能把 `queued` 直接当作正在生成，也不能因为经过 24 小时就悄悄把任务改为 `expired`。

## 执行器必须满足的协议
1. **显式启用**：普通本地聊天保持原有流程。用户启用云端后台功能后才允许提交任务；无需注册账号，匿名设备 JWT 仍须校验。
2. **上下文快照**：在本地确认用户消息和时间线有效后，提交一份大小受限的、与任务绑定的不可变上下文快照；服务端验证所属用户及其版本。仅有消息 ID 不能生成回复。
3. **凭据边界**：不将服务商 API Key 写入仓库、推送订阅、浏览器构建环境变量或明文任务表。若允许 BYOK 云端执行，须先实现可撤销的加密凭据存储、密钥轮换和最小权限解密。没有凭据时必须拒绝入队或立即返回明确失败。
4. **任务状态机**：`queued -> running -> completed -> notified`，失败则转 `failed` 并保留可诊断的受控错误码；取消则转 `cancelled`。每个任务仅允许一次持久化回复；租约和幂等保护并发 worker。
5. **失败规则**：明确的服务商错误、权限不足、余额不足、格式不支持等立即结束；短暂网络异常可在严格限制内重试，重试耗尽立即记为失败。不能无限等待、静默过期或伪造回复。
6. **通知规则**：服务端先提交回复，再判断当前会话前台可见性。聊天界面正在显示时不发系统通知；后台或离开该聊天界面时才推送。通知只包含通用提醒，不含正文或密钥。投递需幂等。
7. **本地合并**：只导入当前会话、当前有效时间线和 epoch、仍以对应用户消息结尾的回复。事务写入消息、版本及时间线；重复同步不得生成第二条回复。
8. **主动消息**：必须有独立、可取消的日程和概率配置，不能借用普通回复任务的用户消息末尾校验；需要单独的安全导入路径。
