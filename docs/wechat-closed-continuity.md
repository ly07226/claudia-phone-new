# 关闭小手机后的微信记忆连续性：实现与边界

## 本轮代码
- `src/wechatClosedContinuity.ts`：每个绑定单独同意，重新打开、切回前台或恢复网络时同步微信云端消息。
- `src/main.tsx`：应用层触发，不要求用户一直停留在微信设置页面。
- `src/WechatIntegrationSettings.tsx`：新增明确的离线连续对话授权开关。
- 仅同步已连接、角色 ID 和会话 ID 均匹配的日常聊天；不修改世界/剧本。
- 消息合并及游标使用现有事务逻辑；冲突、未发出消息、超页时不覆盖云端快照。
- 成功回填后重新使用本地 `buildContext` 构建角色有效上下文，上传个人 Supabase。

## 关键边界
1. 手机关闭时，**云端 iLink 监听器及 AI worker 必须独立运行**，才能接收、保存、回复微信消息；前端不可能在被 iOS 终止后持续运行。
2. 云端数据库会保存已接收微信消息；但当前生成器只读取有限窗口的最近微信消息和最后一次有效上下文快照，**尚无经验证的云端长期记忆压缩/索引**。不能称为无限轮次无损记忆。
3. 关闭期间未上传的本地聊天、世界书或记忆变更无法被云端获知。重新打开后才能更新。
4. 此开关是当前设备本地同意状态，不是跨设备的服务端授权开关；停用 AI 仍需在云端 AI 授权界面操作。
5. 云端监听器/AI worker/发送模块尚未部署或真实联调。SQL、构建、扫码、协议与消息去重均需验收。
6. 同步后云端快照包含微信期间的新消息，旧消息不应再次进入 prompt；需要进一步测试快照截止时间边界和并发收消息竞态。
7. 不应合并 main 或部署 Production，直到完成上述验收。

## 下一阶段

- 实测多轮、断网、锁屏、退出 PWA、重新打开、切换时间线、撤销授权。
- 校验依赖锁文件和全部 SQL 迁移；增加自动化测试。
