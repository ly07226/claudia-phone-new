# Claudia Phone 后台执行与真机验收

**状态：开发方案和维护接口已提交；尚未部署，尚未完成真机验收。**

## 架构必须先解决的问题
当前 `claudia-enqueue-reply` 只接收 conversationId、timelineId、clientMessageId、幂等键和版本号，不接收聊天正文、角色设定或模型配置。它不能被当成可运行 AI 的完整任务。不能在服务器凭空补全角色上下文。

正式的后台 AI 执行器必须满足：
1. 在 iOS 前台发送消息时，先把任务的**完整、版本固定**的上下文快照安全提交到服务端，再允许前台挂起；失败时继续原有前台生成，不能显示虚假的后台成功。
2. 明确用户 AI 服务商密钥的云端使用授权。当前密钥只在本地；禁止上传明文密钥到数据库或日志。需设计可撤销的加密凭据存储（KMS/服务端密钥）、按用户/设备隔离、限额和删除流程。另一种方案是提供平台托管 AI 服务，由运营方承担费用和配额。
3. 服务端执行时核对任务归属、上下文版本、消息分支；任务幂等，锁定并发，限制超时/重试，避免双重扣费。
4. 写入回复后通知对应设备，前端按 jobId/messageId 去重同步；不能把聊天正文放到锁屏通知。
5. 云端主动消息需要独立定时调度和取消机制。

## 已写代码（均未部署）
- `claudia-push-subscriptions`：匿名 Supabase Auth JWT 验证后注册设备订阅。
- `claudia-enqueue-reply`：JWT 验证后创建幂等元数据任务。
- `claudia-send-push`：仅内部密钥调用；仅对已完成、已保存回复的任务发送不含正文的 Web Push。
- `claudia-worker-maintenance`：仅内部密钥调用，过期 24 小时仍排队的任务，返回 `aiExecutionReady:false`。**不是 AI 生成器。**
- `src/cloudIdentity.ts`：无需用户注册的设备匿名身份；浏览器数据丢失时不可自动恢复。

## 部署前必需的核验
- 确认 Supabase Authentication > Providers > Anonymous Sign-ins 已开启；不是面向用户的登录界面。
- 配置前端**公开**变量 `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`、`VITE_PUSH_PUBLIC_KEY`。
- Supabase Edge Functions 配置精确 `CLAUDIA_APP_ORIGIN`。用户接口开启 JWT 校验；内部接口必须先配置独立强随机密钥，再按部署平台网关要求设置 JWT 校验策略。所有 service_role、内部密钥和 VAPID 私钥只在服务端环境变量保存。
- 生成 VAPID 公私钥并配置发送器；验证 Deno npm:web-push 在 Edge Runtime 的兼容性。尚未完成验证。
- 添加服务端任务处理器的真实上下文快照、凭据策略、调度、同步、取消和防滥用后，才开放云端后台生成入口。

## 真机验收（必须实际运行，不是模拟通过）
1. iPhone Safari 添加到主屏幕，从桌面图标打开，允许通知。
2. 开启云端功能：验证匿名身份被建立，用户未看到注册/登录页面。
3. 订阅登记成功；切换其他 App，向已验证的推送发送接口触发测试通知，检查锁屏通知与点击跳转。
4. 发出真实 AI 消息后立即切走，确认服务端仍在独立运行并保存回复；回到小手机正确去重同步。
5. 验证不同设备/用户无法互读任务、订阅和回复；验证密钥不会出现在网络日志或数据库明文字段。
6. 测试取消、超时、重复提交、离线、通知权限拒绝、iOS 系统清理 PWA 进程、服务商限额/错误。
7. 测试通过后才考虑合并 main；未经用户授权不得合并或手动部署 Vercel。
