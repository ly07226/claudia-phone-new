# 微信日常聊天消息存储：部署与验证清单

迁移：`supabase/migrations/20261116000100_wechat_daily_bridge.sql`

## 本批交付
- `claudia_wechat_bindings`：每个用户/日常会话唯一绑定，角色和会话 ID、连接状态。
- `claudia_wechat_messages`：每个绑定下按方向+微信外部消息 ID 唯一，保存文字、状态、时间、租约、重试次数、本地消息 ID。
- 行级安全：authenticated 仅能 SELECT 自己的记录；写入仅允许受控服务端；触发器拒绝跨用户写入绑定。
- **没有**保存微信登录 token、context_token、模型密钥或二维码密钥；凭证设计将在单独安全审计中完成。

## 尚未完成（禁止宣称可用）
- 未将迁移应用到真实 Supabase；未验证数据库策略和执行计划。
- 尚无服务端写入 API、原子抢占任务 RPC、接收/发送回执或重试队列。
- 尚无微信 iLink 扫码、收发、客户端同步或角色记忆共享。
- 该唯一性约束仅防止同一外部消息 ID 被重复插入；**不能**单独保证模型只调用一次或微信只发送一次。发送结果未知时需人工/协议回执确认。
- `local_message_id` 是将来双端同步的映射字段，尚未接入 Dexie。

## 部署前必测
1. 在隔离的测试 Supabase 项目中执行迁移两次，验证幂等性。
2. 用户 A 只能读取 A 的绑定和消息；用户 B 无法读取或写入 A 的记录；匿名角色不可读。
3. 同一绑定+方向+外部消息 ID 并发插入只保留一条；不同绑定/方向不冲突。
4. 跨用户绑定消息写入被触发器拒绝。
5. 删除用户或绑定后关联消息清理正确。
6. 验证索引和大量消息的游标分页，避免无限拉取。
7. 评估现有 Supabase migration 历史和命名冲突；先检查再执行。
8. 增加受控服务端 RPC 后验证并发抢占、超时恢复、回执不确定状态和无重复扣费。
