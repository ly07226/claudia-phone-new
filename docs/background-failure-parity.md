# 后台回复失败行为：与日常聊天一致

用户确认的产品规则（2026-11-14）：
- 不创建新的后台专用失败弹窗或错误文案；复用日常聊天的“发送回复失败”提示、错误详情面板及其关闭方式。
- 一次后台生成中只要 AI 请求已确认失败（包括网络请求抛错、API 返回错误、超时），立即停止该次执行，不自动重试，不等 24 小时，不在后台继续尝试。
- 原始用户消息和当前时间线保留；用户自行决定是否重新生成。
- 若 iOS PWA 已被挂起，服务端保存终态 `failed` 及可展示的安全错误类别；用户回到会话时同步，映射到日常聊天相同的错误展示路径。
- 对于服务器进程崩溃而无法当场报告的情况，使用短租约/超时检测并尽快标记失败；这属于故障检测，不是 24 小时延迟失败。
- 服务端不能返回包含 API Key、完整鉴权头或其他机密的原始错误详情。

当前代码事实：
- `src/generationTasks.ts` 已有 `retainGenerationFailure`、`describeReplyFailure` 和 `useGenerationFailures`；其 `catch` 路径在非主动中止时记录失败并抛出错误。
- 后台 worker 尚未真正实现；因此**尚未**将服务端失败同步接入日常 UI，不能宣称已通过端到端测试。
- 旧的“24 小时排队过期”逻辑已从 `claudia-worker-maintenance` 移除。
