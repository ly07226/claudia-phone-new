## 确认缺陷与修复

1. `summarySourceFingerprint.ts` / `messageBubbles.ts`：main 的显示时间标记清理会改变旧 s3 来源投影。增加稳定的来源投影，显示默认行为不变；旧未修改消息的摘要不会因显示清理失效。
2. `memorySummary.ts`：5000条无指纹旧凭据逐项空异步等待可使 Dexie 提前提交。基线测试复现 `PrematureCommitError`；无异步工作直接返回验证状态，真正 SHA 工作仍保持事务存活，新增旧凭据和旧摘要大容量测试。
3. `importPlan.ts`：相同文件重复合并时无必要添加导入前指纹，导致语义相同记录被判冲突。仅在所有者重映射时增加追踪字段；真实ZIP重复导入、角色冲突复制及多世界测试通过。
4. `memoryStore.ts` / `memoryValidation.ts` / `memoryTypes.ts`：分类清空采用版本墓碑/可选短期掩码；保留自动总结凭据与轮次，避免清空后重新收费。新分支继承先前掩码，已有兄弟分支冻结自身状态；两类修订保护确认到提交间的并发变更。
5. `MemoryApp.tsx` / `MemoryDeleteDialog.tsx`：短期摘要取代原文列表；去掉阅读页面直接触发日摘要调用；加入读取错误/超时/重试，删除后回到列表，分类清空与来源详情，避免大列表编辑重复过滤渲染。
6. `memoryDesktopPresentation.ts` / `store.ts`：满桌面下旧数据缺少记忆图标时不再被裁掉，使用既有桌面容量规则，持久化数据不改。
7. `memoryContext.ts`：同一事务复用验证后的 owner/entries/receipts；只对实际需要的来源核验，选满预算后不再序列化所有剩余候选。保留每次请求的来源验证，不增加跨请求信任缓存。

Linux Chromium、iPhone13视口、无CPU节流，同类合成数据：10000消息、20000手动核心修订、5000零事实总结凭据。自动化耗时包含调度开销，非真机每键延迟、非多轮统计平均。

| 操作 | 上轮本地基线 | 本轮冻结运行 |
| --- | ---: | ---: |
| 记忆读取 | 205.4 | 171.7 |
| 总结状态核验 | 3278 | 1284.9 |
| 路径+记忆上下文 | 2940.8 | 935.3 |
| 进入聊天 | 7182 | 984 |

本轮细分：路径586.2；记忆上下文349.1；Conversation读取37.8；消息读取99.4。仍保存10000原消息；12条事实注入，预算未放宽。进入/输入大幅改善同时包含 main 已有窗口化，不把所有收益归因于本轮记忆优化。

局限：没有大规模混合自动事实的性能基准，没有测量内存峰值；实际中文、图片及复杂分支可能更慢。不能据此承诺真实iPhone或任意数据规模表现。

## 仍未解决与验收边界

- 聊天初始有效路径仍需全量读取/验证；未实现数据库级完全懒加载。
- 核心/长期清空保留墓碑历史，达到修订容量上限时会安全失败；不靠删除历史腾空间。删除也不减少历史修订总量。
- Conversation内嵌大数据仍受单记录及备份现有安全容量约束；没有丢弃正文、图片来绕过限制。
- 短期摘要随已完成总结间隔更新，不是每条消息立即摘要；兼容旧服务响应未返回事件摘要时不伪造摘要、不额外调用API。
- 无法核验的旧摘要和旧自动事实保留可读，但不直接作为可信当前事实注入，需手动确认；这与删除旧数据不同。
- 来源展示节点/消息ID与轮次，不提供点击跳到原聊天；没有保证模型推测检测或语义一致性百分之百准确。
- 390/430截图在 artifacts/memory-v2-{short,long,core}-{390,430}.png。已检查对应浅色页面，未声称全部七主题或真实Safari通过。
- 没有真实iPhone、PWA键盘、后台恢复、收费模型验证；没有升级数据库版本。
- 保持 Draft PR，需用户真机和真实模型验收及容量边界评审后再判断合并；本轮不合并、不发布Production。
