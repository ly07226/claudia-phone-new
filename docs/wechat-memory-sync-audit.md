# 微信记忆同步与撤销并发：阶段验收说明

## 本轮变更
- 快照增加 `history_cutoff`：AI 仅追加快照建立之后的微信消息，避免重复回放旧微信历史。
- 出站领取增加云端 AI `enabled` 和快照存在性约束。
- 发送前再次查询角色授权、绑定状态和快照存在性。
- 设置页增加**明确同意后**的前台定期同步：设置页面保持打开且可见时，每 60 秒以及重新切到前台时刷新；关闭设置页或锁屏不运行。
- 仍支持手动同步、删除云端上下文、停用和删除云端 AI 配置。

## 尚未完成或不可宣称的能力
- 这不是后台自动增量同步：它上传的是有界的有效上下文快照，只有设置页面在前台时才会刷新；iOS PWA 退出后不能依靠本地定时器。
- `history_cutoff` 仅减少旧微信消息的重复回放，不保证跨渠道消息的全局精确去重，也无法证明快照和云端消息完全一致。
- 发送前的授权查询与网络请求之间仍有 TOCTOU 竞态。需要强一致的发送许可/撤销栅栏和已开始请求的语义设计。
- 当前 `claudia_wechat_quarantine_expired` 将过期生成任务标记 unknown；应区分生成可重试与发送不可盲目重试。
- UI 构建、SQL 迁移、真实 iLink 扫码、长轮询、模型 API 和发微信尚未实测。
- `qrcode.react` 的 lockfile 仍需核对更新，CI 未执行。
- 仍需验证 Supabase 自定义域名、服务端运行环境、密钥轮换和所有角色范围隔离。

全部修改仍位于 `feature/wechat-ilink-integration`，不合并 main，不部署 Production。
