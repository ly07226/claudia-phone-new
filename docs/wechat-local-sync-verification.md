# WeChat 日常同步：本地原子游标验收

本轮文件：`src/chatTypes.ts`、`src/wechatDailyMerge.ts`、`src/wechatDailySync.ts`。

- 同步进度存放在原有日常 Conversation 的 `wechatSync` 字段；没有新增 Dexie 表或版本。
- 合并事务同时保存消息、assistant variant、时间线投影和同步游标；事务失败不得推进游标。
- 收到 outbound 未确认 sent 的行时停止推进游标，以免后续发送成功后永久漏入聊天。
- 同步驱动每次最多拉取有限页，遇到未发送行不自旋；没有启用自动轮询。
- 绑定或角色不匹配、时间线切换、发送中均拒绝静默合并。
- 只处理已确认发送的 outbound；生成中的回复不显示为已发出。

## 必须在接入 UI 前解决
1. 同一会话并发同步：必须增加单飞锁/事务级期望游标校验，防止旧页面重复应用。
2. 服务端状态更新通知或独立变化游标：目前通过阻塞待发送行保证不漏，但会延迟其后的消息，且未处理已导入消息的后续状态变化。
3. 小手机消息 -> 云端共享上下文：目前尚未实现；云端不能假装读取了本地 Dexie。
4. 本地用户删除、撤回、编辑、切换分支时的远端冲突策略；需要明确撤销绑定和清除云端数据。
5. 数据库迁移、浏览器运行测试、模拟并发与实际 iLink 联调尚未执行。

## 测试重点
- 同一页重复执行不增加消息；进度与时间线事务同成同败。
- outbound generated -> sent 后下一次同步能补入；不能因早期游标推进而丢失。
- 切换世界、角色或时间线时拒绝合并。
- 旧同步请求返回晚于新请求时不能回退进度。
- 有效的 `local_message_id` 映射不重复生成消息。
