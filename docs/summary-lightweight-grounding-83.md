# 自动总结：宽松提取、轻量核验（Issue #83）

## 目标与边界
不新增收费模型调用；不要求模型逐字引用、轮次、evidence 字段；不限制情绪概括、角色内心推测或剧情发展。避免把模型生成的具体错误事实（数字、明确否定、假设变已发生、用户与角色混淆）写入确定记忆。保留已存在的分支/世界/角色来源隔离。

## 现状（main）
- `memorySummary.ts` 一级调用 `parseSimpleSummary(raw)`，仅做结构/长度/类型筛选。
- `memorySummaryFormat.ts` 有更严格的 `recoverSummaryBatch`，但它要求较强的文本相似/引文证据；**不可直接整体替换**，否则会过滤隐含情感记忆。
- 已有 `fact / belief / speculation / pending` 类型，优先复用。

## 实施顺序
1. 在 `parseSimpleSummary` 之后、checkpoint 持久化之前增加逐条轻量核验；传入**本次请求实际输入的对话**，不得从其他世界/分支找证据。
2. 仅针对可明确识别的硬性冲突作拦截：同一主体的数字/金额/日期反转、明确否定反转、条件或计划改写为已发生、主体混淆。不可仅凭数字不同或出现“不”字就拦截：先匹配主体、事件、上下文；不能可靠判断则保留为推测/待确认，而不是改写原文或自动制造新事实。
3. 情感、关系、意图推断允许合理概括，保留 `belief/speculation`；对“已经结婚”“已怀孕”等具体事件断言不能凭情感推测升级为 `fact`。
4. 逐条筛选并记录 rejected 原因；合法空数组可以成功推进，非空候选全被证实错误时不得伪装为“模型没提取到记忆”。已付费检查点只复用经新验证规则校验的来源，避免静默重调 API。
5. 用独立单元测试先验证纯函数，再做模拟 Provider + IndexedDB 回归。覆盖数字 -100/100/200、否定、计划/已发生、第三方转述、情绪概括、无明确逐字引用、合法空、混合正确/错误、断点恢复、旧备份。
6. Issue #83 的 `response/truncated` 和 `stale-path` 作为独立子修复，不与 PR #82 原文召回混合。不得自动收费重试。

## 验收门槛
- TypeScript/build/相关测试与完整记忆回归有真实日志；不把既有46项失败称为通过。
- 不能通过简单扩大关键词黑名单或强制 evidence 实现。
- 未验收前保持独立分支、不开 Production。
