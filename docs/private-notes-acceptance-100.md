## 缺陷与处理

| 问题 | 原因及位置 | 修复与证据 |
|---|---|---|
| 同一条评论重复请求、重复收费 | `privateNotesGeneration.ts` 的回复入口未校验评论是否已经收到回复，也没有跨窗口守卫 | 现有 themes 表中的短期原子任务租约；核对记录归属、评论位置与原文，保存时再次校验。连续两次请求只调用一次模拟 API，只有一条玩家评论和一条角色回复 |
| 大量日记无法备份 | `privateNotesArchive.ts` 将所有角色的记录、评论及外观聚合在同一条 themes 记录，累计可超出现有 16MiB 单记录限制 | 仍使用 themes 表和原有备份编码，但按原有角色 ID / 记录 ID 逐篇存储，不新建数据库或复杂 ID 系统；1200 篇、正文 UTF-8 合计 18,000,000 字节，ZIP 可校验并写入隔离恢复库，1200 篇完整保留。ZIP 压缩后体积不等于原文体积 |
| 自动任务失败后反复调用 | 原 `pending` Set 仅在当前页面有效，失败立即释放后同一原文可以再次自动请求，跨窗口也不互斥 | IndexedDB 原子领取、180 秒过期保护；按来源指纹保存自动尝试记录，相同来源失败后不自动重发，允许显式手动恢复；不把全文写入租约。两窗口并发只产生一次调用 |
| 定时间隔没有独立检查 | 原页面只在角色切换/进入时执行，另由聊天成功钩子调用，没有前台定时检查 | 私人记录打开且前台时每分钟检查资格，卸载清理监听/计时器，后台不补发。1h / 3h / 240 分钟测试。关闭网页后不承诺执行 |
| 完整 JSON 但输出被截断也保存 | 原调用未消费完成原因，`null` JSON 会发生属性读取异常；超长结果被静默截取 | 使用现有 Provider 完成原因接口，无角色回退重发；长度耗尽/传输中断、空值、格式错误拒绝保存；回复过长拒绝，不截出半句话。失败仍释放执行状态，手动重试正常 |
| 快速切换出现旧角色记录闪现 | 原 notes 状态在新角色读取完成前仍可被渲染 | 区分已加载归属和当前选择，加载中不显示其他角色记录，增加读取失败反馈。迟到生成/回复只更新原角色数据库，不更新另一角色视图 |
| 生成期间编辑或回溯，旧内容仍可保存 | 原代码只在请求前读取聊天，不在保存时核对来源 | 在包含源消息和私人记录的同一事务内核对当前路径、角色会话及源消息前缀；编辑/重新生成/分支改变拒绝保存过期内容；纯追加新聊天不误报失效，也不把未处理的新聊天计入本篇进度 |
| localStorage 旧记录未进入 ZIP | 原 loadNotes 回退到 localStorage，但新 append 只读 IndexedDB，会遗漏旧列表 | 旧格式首次读取后原子持久化到 IndexedDB，再移除冗余本地镜像；旧 aggregate 记录惰性、原子拆分。失败回滚，已有聊天不变 |
| ZIP 合并后日记丢失或归属错误 | `importPlan.ts` 只在覆盖外观时复制普通 themes 行，合并模式忽略私人记录；复制冲突角色时嵌套 characterId 没有重映射 | 新增仅处理私人记录的 `privateNotesImport.ts`，在隔离导入计划里复用已有角色映射和碰撞命名能力；保持本地记录，导入记录跟随复制后的角色，重复导入幂等。QQ / 微信、其他身份、Provider 导入代码不修改 |
| 复制角色后的同 ID 草稿串线 | 原评论草稿/忙碌状态只按 note.id 保存，复制角色保留同一记录 ID 时共用 UI 状态 | 仅 UI 状态使用现有角色 ID + 记录 ID 组成键，不新增业务 ID；先复现 B 输入框出现 A 草稿（1 失败），修复后切换双方草稿独立 |
| 后台写作已保存，列表仍不刷新 | 页面初次读取后不订阅 IndexedDB；聊天页面发起的请求若在进入手记后才完成，当前页的生成调用返回 pending/null，不会刷新列表 | 用 Dexie liveQuery 按当前角色读取，每次切换/卸载取消旧订阅；后台生成结果完成后无需切换/刷新即可出现，先失败复现再修复 |
| 长内容及 iOS 输入体验 | 长词可能越过卡片；13px 评论输入会触发 iOS 聚焦放大 | 仅私人记录命名空间增加长词换行和输入框 16px，不改全局样式、卡片布局或导航 |

最初三项失败复现：重复回复调用数、超过备份单条限制、失败自动再次调用，**3 失败 / exit 1**；修复后同一组 **3 通过 / exit 0**。没有删除或降低断言。

## 行为边界

- 日记、备忘、梦境仍按角色独立保存；只读取该角色 Daily scope 会话，不读取其他角色或 World 私有聊天。
- 日记/备忘共享原有非梦境进度；梦境仅显式触发，不推进日记游标。今日/旧日的聊天日期标签和“旧记忆仅作背景”约束保留。
- 评论失败时玩家评论已保存，末尾未回复评论提供手动重试；重试不再次插入玩家评论。回复仍由该篇记录对应角色生成。
- API 失败不自动重试；生成不会阻塞聊天。服务端已计费但浏览器崩溃的场景无法证明模型是否完成，不能声称跨崩溃绝对 exactly-once；不会静默重新付费请求。
- 设置采用原有全局私人记录外观/间隔语义，没有拆成新的角色配置。合并保留当前外观，覆盖且选择外观范围才采用来源外观，沿用导入选择语义。
- 旧 aggregate 和旧 localStorage 数据可读，数据库版本与 ZIP 协议不变。没有取消加密 ZIP、旧 ZIP、默认不含 Key、显式导入 Key 的保护。
- 单篇记录/评论总量新增 2MiB 写入保护，超过时明确拒绝本次写入并保留已有数据；不截取或删除原记录来通过备份。总备份仍受已有 ZIP 容量、浏览器内存和设备存储限制。

## 真实数据库证据及 UI

- 使用真实浏览器 IndexedDB/Dexie 读写，而非只测试 JSON 解析。
- 网络/截断/JSON/null/空响应失败后无新记录；手动恢复可保存。
