# Issue #24：Story 剧情连续性端到端审计与有界修复

关联：Refs #24（本轮不关闭）。

审计日期：2026-11-12。基线 main：`294b6bb7b28a28f074acbc8a2f7f5f4874fa4b96`。独立分支：`fix/story-continuity-audit-24`。没有访问用户生产数据库、私人剧情或真实 API，没有合并 main 或发布 Production。另一产品的 400 回合体验仅是目标，不是本仓库曾具备的能力。

## 结论

现有系统有完整节点存档、有效路径回放和**有限的原文摘录记忆**；不是自动更新的叙事事实账本，也没有普通故事的人物状态总结器。保存完整历史不代表模型看到了全部历史。本轮在真实请求构建路径确认并修复了五项前情漏传/召回问题；不能据此断言用户那次“12轮3次逼宫”只有同一个根因。

A 类（前情未正确提供）已用合成场景复现。B 类（正确前情已提供，模型仍输出矛盾）另有刻画测试：解析器会接受格式合法的矛盾正文；它不是语义事实审核器。本轮没有以关键词封禁、硬编码剧情或新增强制审核来掩盖 B 类问题。

### 信息分层

- 原始设定：`definition`、`simulatorRules`、原文开场/方向；计划不是事件队列。
- 历史证据：`confirmedHistory` 和 `longTermStoryMemory.excerpts`；摘录可能包含对白、计划、传闻，不能宣称都是客观事实。
- 玩家意图：`selectedAction`、近期行动记录、此次新增的有来源旧行动引用；不能直接当成成功结果。
- 当前状态：有声明运行配置时从本路径 `simulatorChanges` 重放；普通叙事只能根据带来源原文判断，没有权威动态人物表。
- 未来可能性：原文方向、未兑现承诺、条件和猜测原样保留，不自动转成历史事实。

### 其他确定性改进

- 摘录包含源节点 ID、序号及 body 内 UTF-16 起止位置；测试核对 `body.slice(start,end) === text`，不截断条件、否定或句子。
- 历史重复文本不再全局按去空白文本合并，避免不同发生次数失去出处。
- 更老玩家行动与正文分开保存为请求侧 `actions`，标注意图；未改数据库结构。
- 请求元数据说明静态计划/已提交证据/当前状态限制；没有修改既有基础 system prompt、人设、剧情风格或自由行动。
- 数值诊断增加候选数、选中历史字节、分配额度、旧行动数；不新增正文、节点 ID、URL 或密钥日志。

## 3. 尚未确认的风险

1. 用户真实重复事件没有完整的那一轮请求、有效路径和模型原始输出，不能证明已修复其所有成因。
2. 词法召回不是语义记忆；未在行动/近景中提及的重要人物、别名、同义表述可能漏召回，预算也不能容纳全部历史。本轮没有向量索引或事实摘要器。
3. **B类已刻画但未消除**：测试先提供“郑砚殒命并下葬”，下一次Mock仍返回其正常值守，合法正文照常提交。这证明缺少语义矛盾裁判，不能用此Mock评价任何真实模型。
4. 普通故事没有持久的人物/世界状态账本。模拟器字段与正文可能各自格式合法但语义矛盾；现有类型校验不等于语义校验。
5. 64KB 是程序字节上限，不是逐Provider精确Tokenizer或上下文窗口适配；必要资料太大仍会准入拒绝。未通过调低输出、静默裁原文或多次API来掩盖。
6. 对背景必要句的既有规则判断仍是启发式；并非完美语义分类。正文中无句号的超长单元可能整体放不进摘录；不会切掉一半假装完整。
7. 多分支以当前head父链为准；当前撤回/重生会删除被替换叶节点，不是永久保留所有候选的版本图。本轮没有改变这个已有产品行为。
8. 未发现测试中有跨世界串线、失败响应推进两次、旧分支进入有效记忆的问题；这不是证明所有设备/并发状况绝无错误。

## 5. 成本、兼容与长期能力

没有额外 API 调用、付费总结、后台循环、输出 Token 增加、数据库版本变更、人物卡或历史文本改写。**输入 Token 不保证不增加**：短回复场景保留更多证据，比基线可能增加输入计费；历史目标16–32KB，总请求仍≤64KB UTF-8字节。较大输入也可能提高服务商延迟，不能可靠换算时不编造价格。

现有2000节点容量和有效路径回放为数百回合提供存储/分支基础；本轮120/400节点实验支持有界、可溯源的特定事实检索。**不能认证100–400回合真实剧情持续一致**。这还依赖语义召回、状态更新质量、模型能力及真实剧本评测。
