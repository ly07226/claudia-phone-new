# 微信常驻监听器（开发版，尚未部署）
运行方式：Node.js 20+，单副本进程 `node workers/wechat-listener.mjs`。
只连接当前使用者**自己的** Supabase；不要把多个用户的项目凭据配置到同一个进程中。

## 环境变量
- `SUPABASE_URL`：自己的 Supabase 项目 URL
- `SUPABASE_SERVICE_ROLE_KEY`：仅服务端使用，禁止放入 VITE_* 或网页
- `WECHAT_ILINK_ENCRYPTION_KEY`：32 字节随机值的 Base64；必须与微信登录云函数使用的值相同

## 前置条件
1. 执行微信模块 SQL 迁移至 `20261116001000`。
2. 部署并配置微信扫码登录函数，使用自己的 Supabase 项目扫码成功。
3. 在独立常驻服务中运行监听器，不要部署成 Vercel 静态网页或普通短时请求函数。
4. 只运行**一个副本**。目前没有分布式锁，多副本会发生游标竞态。
5. 持续保存同一套加密密钥；更换密钥前需迁移密文。

## 现阶段能力与限制
- 每次从私有游标调用 iLink `getupdates`，将纯文字消息及其加密回复路由写入自己的数据库。
- 所有支持的文字入库成功后才推进游标；重复收到消息按外部消息 ID 去重。
- 不处理图片、语音、群聊权限策略和复杂会话；尚未实现账号恢复和设备迁移。
- 当前代码**不包含 AI 生成 worker**，不会因为监听器启动就自动生成回复。
- 已有发送函数 `claudia-wechat-send` 需要独立调度和完整测试。
- 需要测试 iLink 真实协议的返回字段、长轮询超时、断线恢复、发送上下文、限流和账号限制。
- 微信数据仍然会在使用者自己的 Supabase 中；网站维护者的 Supabase 不应接收它们。
- 云端要调用用户 AI API，需要单独授权和安全密钥存储；不能从已关闭的 iPhone 读取本地 Key。

## 安全注意
- 任何日志均不应输出 token、消息正文、peer、context_token 或 API Key。
- 当前仅支持单项目单进程、文字消息，不能当作已验收的生产服务。
- iLink 能力及可用性可能变化；上线前需核对官方协议和使用条款。
