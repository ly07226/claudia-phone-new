# 忍一下嘛 · 整合分支

工作分支为 `integration/story-phase-play-preview`；只从 Daily ChatHub 的聊天标签进入，通过既有 phonePageNavigation 返回。没有修改聊天生成、世界书、记忆、主题数据库或 Story 业务。

## 游戏与反馈

红/黄/绿的阶段计时与整局5/10/15/20/50分钟倒计时独立。整局结束不再切阶段或抽卡；可主动重新开始。阶段可顺序/随机切换，使用固定或随机时长。

每个阶段分别维护已抽卡片队列；当前组合卡片与普通自定义卡片共同参与，没有卡片时使用内置指令。耗尽后重新抽取，至少两条时避免紧接着重复上一条。新增、删除后按仍有效的ID更新队列。暂停和刷新保留队列；新局清空。

30–180 BPM，自动加速只改变节拍，不改变阶段时长。声音、视觉和可选震动使用同一节拍事件；减少动态效果时禁用动画。音频需要用户操作解锁；暂停/退出/结束取消现有声音和迟到的解锁。iOS通常没有Vibration API，不能声称真机震动可用。

只累计前台活跃时间。后台、pagehide、锁屏、事件循环停顿超过1.5秒均保守暂停；刷新恢复暂停，不补跑离线阶段。改变暂停中的玩法或词库归属会准备新局并明确提示；调整音量等反馈偏好不重置计时。

## AI词库

选择已有角色及可选世界。使用角色绑定的API或全局默认配置，保留原模型、密钥、温度和输出上限；不读取聊天记录、聊天记忆或朋友圈上下文。所选世界必须存在与角色关联的资料。

默认每次追加30条（每阶段10条）；另有明确的重新生成按钮，在付费请求之前确认替换。按现有输出上限规划小批次（例如1024上限每批4条，共8次）；UI提示进度、额外调用和取消方式。每批最多90秒；没有自动重试或角色消息回退请求。游戏中只读本地词库，不发AI请求。

严格验证JSON、任务编号、数量、可选phase、文本及规范化重复；截断或任何一批失败均不写入半套结果，原词库保持不变。全部成功后原子保存词库和历史。手动卡片可新增、编辑、删除；历史版本可恢复。生成期间更改设置或离开会取消，结果不会写入其他组合。

每个角色＋世界组合最多1000条，全应用最多20000条；最近10份历史纳入同一v1记录。总序列化大小上限3MiB，浏览器配额可能更低；失败不删其他配置。超大角色/世界输入在请求前明确拒绝，不静默裁剪为完整资料。真实模型是否遵循格式仍取决于服务商；Mock通过不代表真实模型通过。

## 本地兼容与隔离

主键沿用 `claudia.phasePlay.v1:<数据库名>`，新增可选字段，不升级Dexie。词库使用编码后的角色＋世界前缀。旧版选中角色的无世界词库可兼容迁移；不把现代世界词库误认为旧ID。旧版 `versions.v2` 历史仍可读取，不主动删除。

每秒只写入带revision的轻量session检查点，不反复序列化大型词库。保存设置/词库时原子更新主记录；仅接受与主记录revision匹配的检查点。损坏记录不会静默覆盖，重置需用户明确确认且只影响本应用。

应用数据仍只在当前浏览器，**尚未加入ZIP备份**；未改变原ZIP格式或备份恢复。未保存的编辑框草稿不承诺刷新恢复。
