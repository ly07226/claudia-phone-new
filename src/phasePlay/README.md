# 忍一下嘛 · 第一阶段

开发分支：`feat/renyixiama-phase-one`。这是独立的通用阶段互动基础设施；没有 AI 请求、角色读取、聊天上下文、世界书或记忆读写。

## 模块与入口

- `PhasePlayApp.tsx`：独立页面、用户操作和前台时钟。
- `engine.ts`：可注入随机数的纯状态机；顺序/随机切换，固定/区间时长，阶段提示。
- `feedback.ts`：应用独占的 Web Audio 与可选振动，退出释放资源。
- `storage.ts`：独立 localStorage 记录及 v1 校验，不写 Dexie 或 themes/global。
- `phasePlay.css`：独立 `.phase-play*` 样式和现有主题语义变量。
- Daily `ChatHub` 聊天页入口 → `openPhoneApp` → 原有页面返回栈。没有桌面、World、会话或设置入口。

## 保存与生命周期

存储键为 `claudia.phasePlay.v1:<Dexie数据库名>`。设置、已保存提示与计时快照本地保存；尚未点击“添加/保存”的提示编辑草稿不持久化。

运行时使用单调时钟的真实前台耗时，约每秒保存一次快照。暂停、页面退出、隐藏和 pagehide 时保存暂停状态；刷新恢复一律暂停，不追赶离线阶段。事件循环单次间隔超过1.5秒也保守暂停；系统冻结前没有执行保存的机会时，最多恢复至最近一次已成功写入快照。

损坏/未知版本记录不会静默覆盖；用户明确确认后只重置本应用记录。存储失败保留当前页面状态并显示错误，不能保证跨刷新保存。

本阶段新数据**不在现有 ZIP 备份范围内**，不改变旧备份格式、数据库版本或恢复行为。后续如需备份本应用数据，应先设计可选配置与导入校验，不把它混入聊天历史。

## 移动端限制

音频默认关闭，用户主动开启或开始时尝试解锁；浏览器拒绝时继续提供计时和视觉反馈。仅运行且节拍开启时反馈。iOS Safari 通常无 Vibration API；不会声称能震动。后台/锁屏不承诺持续音频或计时，回到前台需要手动继续。

没有修改全局视口高度、底部导航或现有聊天 CSS。该应用不包含、也不宣称修复现有 iPhone standalone 白边问题。

## 后续扩展

阶段状态与提示数据已经独立建模。后续角色联动需要新增独立任务与授权上下文模块，第一阶段不预先挂接 Provider、朋友圈服务或聊天记忆。

## 真机验收

1. Daily 聊天列表进入，使用顶部返回和“快速退出”各返回一次；验证列表位置。
2. 设置三阶段和随机区间，开始、暂停、继续、下一阶段与重置。
3. 开启声音并调音量；切换静音模式/音频权限，确认失败仍可退出。震动只按浏览器实际支持判定。
4. 编辑长提示并保存、删除、刷新重进；未保存草稿离开会丢弃。
5. 中文键盘输入、滚动到底、横竖屏、Safari/PWA与深色主题检查。
6. 后台/锁屏再返回应为暂停，不补跑阶段，不发生网络调用。
